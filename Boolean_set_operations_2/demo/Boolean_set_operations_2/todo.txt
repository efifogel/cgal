1. Algebraic curves
- Implement the Approximate_2 functor of Arr_algebraic_segment_traits_2, in particular the operator that approximates
  an x-monotone curve (by a polyline, given an error bound), as in the other traits. Then use it to draw the arcs
  instead of the fixed sampling of algebraic_arc_points().
- Files (.aps): a set after operations is not described by equations alone, so arcs need their curve, arc number,
  and endpoints.
- Python programs (the log has a comment instead) and the console.
- Other ways to choose the region of a curve (e.g., p <= 0, which may be unbounded) could be offered.
- Semantic errors of equations (a divisor or an exponent that is not a constant) have no column.

2. Polycurves
- Only Segments can be the subcurve family of Polyline/Polycurve. Next: polycurves of circle segments (.pcps), conics
  (.pqps), and Bezier curves (.pbps); then nested ones (.pplps, ...). The suffix scheme is documented in Polygon_io.h.
- Let the user choose the vertices of a polyline polygon (e.g., a modifier key while clicking); the .plps format
  would need to mark them, since now it holds only the vertices and the reader subdivides again.

3. Python programs
- The circle-segment and conic programs were not run, because the bindings (CGALPY_kerEpec_aos2Cs_bso2,
  CGALPY_kerEpec_aos2Conic_bso2) are not built yet. Check:
  - Integer is constructed from a Python int only (init_implicit<int>), so coefficients beyond 32 bits fail;
  - squared_distance() (defined in the program) relies on the arithmetic of Ker.FT;
  - Traits.Point_2 of the conic traits is constructed from floats (Algebraic from double);
  - Result.COLLINEAR (for segments) exists;
  - polygon() filters the results of make_x_monotone with isinstance(o, X_monotone_curve_2).
- Polygons read from files are not logged, in any family, so a program misses them.
- The Bezier, polyline, and algebraic families are not logged; the console supports linear polygons only; the
  Minkowski sum is not logged.

4. Small items
- The polycurve tool bar pushes the Operations panel down; in a small window the bucket rows scroll. The empty curve
  tool bar (for families without tools) keeps its height.
- The message that switches the family uses the internal names ("linear polygons"), not the labels ("Segments").
- help/about_demo.html is out of date (e.g., "Insert Linear polygon").
- The GUI regression scripts (drawing, undo, files, console) are not in the repository; their references predate the
  new tool bar and the polyline marks.

  polygons fails in Arr_walk_along_line_point_location (number_of_outer_ccbs() == 1). Fix it, then drop
  Algebraic_traits (oblivious sides) from Typedefs.h.
